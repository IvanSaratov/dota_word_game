# Быстрый автоматический ввод слов в мини-игре

## Цель

Создать нативную утилиту для Windows, которая захватывает выбранную пользователем область мини-игры, находит одно или два падающих английских слова, распознаёт целевой текст и вводит только латинские буквы с минимальной задержкой.

Целевой показатель — не более 40 мс для большинства распознаваний на подходящем компьютере после появления слова в доступном кадре. Фактическая задержка зависит от частоты обновления экрана, режима отображения игры и производительности компьютера.

## Ограничения и допущения

- Игра работает на Windows и не предоставляет программного доступа к тексту.
- Мини-игра занимает фиксированную прямоугольную область внутри большего игрового окна.
- В области одновременно находится одна цель, иногда две.
- Целевая строка отображается крупным шрифтом из заглавных латинских букв.
- Над крупной строкой может отображаться её маленькая зелёная копия; она не является отдельной целью.
- Цель перемещается сверху вниз и может появляться в разных горизонтальных позициях.
- В сложных целях встречаются пробелы и знаки препинания. Игра не требует их ввода.
- После ввода последней буквы цель засчитывается автоматически. Нажатие `Enter` не требуется.
- Предпочтителен оконный режим без рамки. Эксклюзивный полноэкранный режим может препятствовать захвату изображения.

## Выбранный подход

Используется гибридный конвейер:

1. Быстрый нативный захват выбранного региона.
2. Поиск крупных строк средствами компьютерного зрения.
3. Распознавание только найденных строк компактной OCR-моделью.
4. Проверка результата на соседнем кадре.
5. Отправка букв одним пакетом через Windows `SendInput`.

Полный OCR кадра не используется: он медленнее и чаще захватывает элементы интерфейса. Распознавание только по заранее собранным шаблонам букв также не используется в первой версии, поскольку оно требует полного набора образцов и хуже переносит изменение масштаба. Кэш нормализованных изображений может ускорять повторяющиеся цели без изменения основного алгоритма.

## Архитектура

Утилита реализуется как нативное приложение C++ для Windows. Она состоит из следующих независимых компонентов:

### Выбор области

- Горячая клавиша `F7` открывает режим калибровки.
- Программа фиксирует текущий экран и позволяет мышью обвести область мини-игры.
- Регион сохраняется относительно границ игрового окна, а не в абсолютных координатах монитора.
- Перемещение игрового окна не требует повторной калибровки.
- При изменении размера окна или разрешения пользователь повторяет калибровку.

### Захват кадров

- Используется DXGI Desktop Duplication.
- Из полного кадра немедленно вырезается только настроенный регион.
- Кадры не сохраняются на диск в рабочем режиме.
- Захват работает непрерывно, пока автоматика включена.

### Поиск целевых строк

- OpenCV выделяет яркие символы и группирует компоненты сходной высоты, расположенные на одной строке.
- Размер символов вычисляется относительно высоты выбранного региона, чтобы допускать небольшое изменение масштаба.
- Фиксированные зоны счёта, таймера и рекорда исключаются только в пределах выбранного региона, если они туда попадают.
- Маленькая зелёная копия отбрасывается по высоте символов и цвету.
- При наличии нескольких кандидатов каждый передаётся распознавателю отдельно.

### Распознавание

- Компактная ONNX-модель работает в режиме распознавания одной строки без повторного поиска текста.
- OCR возвращает исходную строку и оценку уверенности.
- Результат нормализуется в верхний регистр.
- Из результата удаляются все символы, кроме `A`–`Z`.
- Пробелы, дефисы, апострофы и другая пунктуация распознаются для понимания структуры строки, но не отправляются игре.
- Пустой результат, строка без латинских букв или результат с недостаточной уверенностью отклоняется.

Примеры нормализации:

```text
DON'T PANIC!  -> DONTPANIC
ROCK-'N'-ROLL -> ROCKNROLL
```

### Подтверждение и выбор цели

- Кандидат подтверждается одинаковым нормализованным результатом на двух последовательных кадрах.
- Небольшое перемещение строки между кадрами допускается.
- Если одновременно подтверждены две отдельные цели, первой выбирается цель с большей координатой `Y`, то есть ближайшая к нижней границе.
- Многочастная фраза внутри одной визуальной строки остаётся одной целью.
- После отправки слова его текст и последняя позиция временно блокируются.
- Блокировка снимается, когда цель исчезает, существенно меняет изображение или покидает окрестность последней позиции.
- После исчезновения первой цели оставшаяся цель может быть обработана без ожидания нового появления.

### Ввод

- Ввод выполняется только тогда, когда настроенное игровое окно находится на переднем плане.
- Все пары `key down`/`key up` для букв передаются одним вызовом Windows `SendInput`.
- `Enter`, пробелы и знаки препинания не отправляются.
- Межсимвольная задержка по умолчанию равна нулю. Если игра пропускает события, в настройках допускается включить минимальную регулируемую задержку.

### Управление и безопасность

- `F8` включает и выключает автоматическое распознавание и ввод.
- Повторное нажатие `F8` служит немедленным аварийным отключением.
- По умолчанию доступен сухой режим: распознанные слова и метрики выводятся в консоль, но клавиши не отправляются.
- Ввод не производится при потере фокуса игрового окна, низкой уверенности OCR или неоднозначном разделении целей.
- Консоль показывает состояние, распознанный и нормализованный текст, уверенность и время обработки.

## Поток данных

1. Пользователь выбирает игровое окно и калибрует регион мини-игры через `F7`.
2. Пользователь включает сухой или рабочий режим через `F8`.
3. Захватчик получает новый кадр и вырезает настроенный регион.
4. Детектор возвращает крупные текстовые строки.
5. OCR распознаёт каждую строку.
6. Нормализатор оставляет только латинские буквы.
7. Трекер сопоставляет кандидатов с предыдущим кадром и подтверждает стабильные результаты.
8. Планировщик выбирает нижнюю из подтверждённых целей.
9. Защита проверяет фокус окна, уверенность и отсутствие повторного ввода.
10. Модуль ввода отправляет буквы одним пакетом.
11. Трекер ждёт исчезновения или изменения цели и затем снимает блокировку.

## Конфигурация

Небольшой конфигурационный файл хранит:

- идентификатор или шаблон заголовка игрового окна;
- регион мини-игры относительно окна;
- режим работы: сухой или рабочий;
- минимальную уверенность OCR;
- допустимый диапазон относительной высоты целевых букв;
- максимальное смещение цели между соседними кадрами;
- необязательную межсимвольную задержку;
- назначение горячих клавиш.

Значения, влияющие на распознавание, имеют безопасные исходные настройки и могут быть изменены без пересборки приложения.

## Обработка ошибок

- Если окно игры не найдено, программа не запускает захват и сообщает причину.
- Если сохранённый регион выходит за новые границы окна, программа требует повторной калибровки.
- Если DXGI-захват недоступен, программа сообщает о несовместимом режиме отображения и предлагает оконный режим без рамки.
- Если OCR-модель не загружена, автоматический ввод остаётся отключённым.
- Если два кандидата визуально слились и не могут быть надёжно разделены, кадр пропускается.
- Ошибки отдельных кадров не завершают программу; цикл продолжает работу со следующим кадром.

## Проверка

### Модульные тесты

- Нормализация регистра, пробелов и всех поддерживаемых видов пунктуации.
- Отказ от пустых и нелатинских результатов.
- Выбор цели с большей координатой `Y`.
- Подтверждение на двух кадрах с допустимым смещением.
- Защита от повторной отправки той же цели.
- Снятие блокировки после исчезновения цели.

### Проверка на изображениях

Фиксированный набор кадров должен включать:

- одну цель в разных частях области;
- две одновременные цели;
- короткие и длинные слова;
- фразы с пробелами;
- дефисы, апострофы и другие знаки препинания;
- яркий и сложный фон;
- частично введённые или изменившие цвет буквы;
- элементы HUD и маленькую зелёную копию строки.

Тесты проверяют найденные границы, исходный OCR-текст, нормализованный результат и выбранную цель.

### Интеграционная проверка

1. Запустить сухой режим поверх реальной мини-игры.
2. Убедиться, что вывод совпадает с целями и не реагирует на HUD.
3. Измерить среднюю задержку и 95-й перцентиль отдельно для захвата, детектора и OCR.
4. Включить ввод на низкой скорости игры.
5. Проверить отсутствие повторного ввода и корректный выбор при двух целях.
6. Проверить мгновенную остановку по `F8` и отсутствие ввода при потере фокуса.

## Результат

Поставка включает:

- запускаемый файл Windows `.exe`;
- файл OCR-модели;
- файл конфигурации;
- краткую инструкцию по калибровке, сухому режиму и горячим клавишам.

Python и среда разработки пользователю не требуются.
